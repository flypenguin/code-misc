# Local WordPress mirror

Runs a local copy of a WordPress site from a database dump and a `wp-content` backup.
Works with `podman compose` and `docker compose`.

## TL;DR

```sh
make up WP_ARCHIVE=wp_content.tar.zst DB_ARCHIVE=wordpress.sql.zst
```

Log in at <http://localhost:8080/wp-admin> as any administrator, password `admin`. `make up` sets it on
every run and prints the admin logins. Every administrator also gets the application password `admin`
(named `local`) for REST clients, e.g. `WP_URL=http://localhost:8080 WP_USER=<admin login> WP_APP_PASSWORD=admin` for [wp2hugo.py](../../tools/wordpress-scripts/wp2hugo.py).

## Usage

```sh
# one backup holding both the SQL dump and wp-content:
make up WP_ARCHIVE=path/to/backup.tar.gz

# separate backups:
make up WP_ARCHIVE=path/to/wp-content.tar.gz DB_ARCHIVE=path/to/db.zip

# or put dump.sql (or .sql.gz, .sql.xz, .sql.zst) into this directory yourself
```

Open <http://localhost:8080>. `.envrc` stores both archive paths, so later runs need no arguments:
`make up`. Archive paths given on the command line replace the stored ones; `WP_ARCHIVE=` clears
one.

| Target       | Effect                                                                              |
| ------------ | ----------------------------------------------------------------------------------- |
| `make up`    | Unpack missing inputs, inspect the dump, start, rewrite the site URL                |
| `make down`  | Stop the containers, keep all data                                                  |
| `make clean` | Stop and delete `data/`; keeps the dump, the archives and `.envrc` (alias: `reset`) |

`make up` runs these steps:

1. [unpack-wp-content](unpack-wp-content) unpacks `WP_ARCHIVE` (tar in any compression, zip, or a
   directory) and moves the shallowest `wp-content` directory in it to `data/wp-content/`. It runs
   only when `data/wp-content/` is missing, so after `make clean`.
1. [unpack-db-dump](unpack-db-dump) moves the shallowest SQL file (`*.sql`, `.sql.gz`, `.sql.xz`,
   `.sql.zst`; ties sorted by name) from `DB_ARCHIVE` to `data/dump.sql*`. It runs only when
   `data/dump.sql*` is missing, so after `make clean`. `DB_ARCHIVE` defaults to `WP_ARCHIVE`.
   `data/dump.sql*` wins over a hand-placed `./dump.sql*`.
1. [inspect-dump](inspect-dump) reads database name, table prefix, site URL and the matching DB image
   from the dump and writes them, plus both archive paths, to `.envrc`.
   [docker-compose.yml](docker-compose.yml) uses its `WP_*` variables.
1. The DB image imports the dump on its first start, when `data/mysql/` is empty.
1. `wp search-replace` rewrites the live URL to `http://localhost:8080`. It handles serialized PHP
   data correctly, `sed` on the dump does not. On later runs it finds nothing to replace.

WordPress core comes from the image. `WP_HOME` and `WP_SITEURL` in `WORDPRESS_CONFIG_EXTRA` fix the
URL WordPress uses, independent of the database.

Choose the compose command explicitly with `make up COMPOSE='docker compose'`. Set the PHP version of
the live site in the image tags of `docker-compose.yml`.

## Layout

```
wp-compose/
  dump.sql            # optional input, used when DB_ARCHIVE is not set
  .envrc              # generated by inspect-dump
  data/
    dump.sql.zst      # unpacked from DB_ARCHIVE, keeps its compression
    mysql/            # database, created on first start
    wp-content/       # unpacked from WP_ARCHIVE
```

## Log in

```sh
. ./.envrc
podman compose run --rm --no-deps cli wp user list
podman compose run --rm --no-deps cli wp user update LOGIN --user_pass=admin
```

## Pitfalls

| Symptom                              | Cause                                                                | Fix                                                      |
| ------------------------------------ | -------------------------------------------------------------------- | -------------------------------------------------------- |
| Redirect to https or the live domain | SSL or security plugin, `.htaccess`                                  | `wp plugin deactivate PLUGIN`                            |
| White screen, HTTP 500               | Plugin needs a different PHP version                                 | Change image tags, check `podman compose logs wordpress` |
| Links still point to the live site   | Only the exact `siteurl` value is replaced, not http/https variants  | Run `wp search-replace` for the variant                  |
| Broken layout, missing assets        | Caching plugin (`wp-content/advanced-cache.php`, `object-cache.php`) | Rename those files, deactivate the cache plugin          |
| Mirror sends real mails              | Contact forms, WooCommerce, WP cron                                  | Deactivate mail plugins before clicking around           |
